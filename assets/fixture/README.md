# `assets/fixture/` — fixture v1, vendored

Fixture v1 (simulation-repo **Phase 4**) is here, brought across by `tools/vendor_fixture.py` and pinned. This file read *reserved, empty — not yet built* until M2 landed it; the rest of it was written as a forecast and held, so what follows is now a description.

**What it carries**, per decisions 872, 889 and 296: field-condition quantities at
`coarse`/`fine` only, with the carried set *reusing the emitter's derivation rule* rather than any
list; taxon-dimensioned quantities pre-aggregated to life form at build time; contours pre-extracted
server-side at the aggregated rung (M4 — they live in `assets/contours/`, not here); and two named daily windows regenerated by replay.

**Its manifest carries the producing build's provenance and its acceptance verdict**, and that
travels with the data on purpose, so one build's demo is never mistaken for another's. **Do not
render the fixture without surfacing the manifest's verdict somewhere a viewer will see.** The
verdict's own values belong to whichever build ships and are read from the manifest, not from here.

**Flow reads the float64 layer, never the float32 one** (§23.812). A float32 copy of streamflow
underflows.
